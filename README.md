# 高校路演成果转化

记录高校学生项目从路演准备到成果转化的多方协作。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括学生创业团队、高校运营人员、产业导师、投资机构。

资料所依据的领域事实如下：

- 平台连接青年创客、政府、创投机构和创业校友
- 服务覆盖项目打磨、资源对接、成果转化和产业落地
- 现场同时设置路演和多类咨询交流区域

## 项目转化流程

`src/pipeline.py` 把一次路演经历实现为连续流程，阶段顺序为
打磨 → 路演 → 验证 → 落地，由 `src/versioning.py` 提供版本化记录与只追加事件日志：

- **版本联系**：项目档案、校内审批（披露/伦理/权属）、技术证明（专利申请、查新、伦理审查）、路演材料、展示安排均为不可变版本，以 `类型:编号#vN` 精确互链；展示安排锁定具体材料版本，材料引用审批与证明的具体版本。`RecordBook.lineage` 可沿版本链回溯。
- **旧记录可查、责任明确**：团队拆分、材料撤回、评委回避、重复反馈、投资意向失效都只追加事件，旧版记录保留；每类事件指定后续责任人（交接、清理、归并、跟进），由闭环事件收尾。
- **商业秘密**：`src/access.py` 仅放行给签署披露约定的投资人与产业导师，放行留痕；含秘密的材料须先获校内披露批准，未签约方看到脱敏内容。
- **投资方视角**：投资意向生效期间可获持续更新授权；意向到期或撤回即停止推送，失效前的推送记录仍可查。投资人承诺的下一次沟通登记为跟进事项，到期可判定 `pending / kept / broken / expired`。
- **评审秩序**：与项目有利益关系的导师不得安排为评委；临场回避后安排续版、回避前意见失效；同一评委对同一要点的重复提交标记为重复反馈并指定归并责任人。
- **学校核对**：落地门禁只认权属清晰、伦理合规与实际转化结果（合同、许可、投资到账、试点采用、收入），明确拒绝以到场人数登记成效。

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实和约束。运行项目自带测试即可检查这些基础资料与转化流程能够稳定运行：

```
python -m unittest discover -s tests
```

仓库不保存账号、密钥、连接串或真实身份信息；示例中的人名、机构名均为虚构。
