# 高校路演成果转化

记录高校学生项目从路演准备到成果转化的多方协作。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括学生创业团队、高校运营人员、产业导师、投资机构。

资料所依据的领域事实如下：

- 平台连接青年创客、政府、创投机构和创业校友
- 服务覆盖项目打磨、资源对接、成果转化和产业落地
- 现场同时设置路演和多类咨询交流区域

## 项目转化流程

`src/pipeline.py` 把一次路演经历落成连续的项目转化流程：

- **版本联系**：项目档案、校内审批、技术证明、路演材料、展示安排各自形成版本链。新版本记录被取代的版本，并快照发布时所依据的其他材料版本；技术证明须以在效的校内审批为依据，展示安排须先完成披露确认（成果披露批准、成员贡献登记、专利申请提交、导师利益关系申报）。
- **商业秘密**：标记为机密的材料与进展更新，仅向签署有效保密约定的投资机构与产业导师开放；约定过期或撤销后即不可见。
- **只增不删的事件**：团队拆分、材料撤回、评委回避、重复反馈、投资意向失效均追加记录，旧记录可查，每条事件写明后续责任人。拆分时新项目链接原项目并保留贡献记录；回避评委的评分不计入但保留；失效意向仍可追溯。
- **阶段推进**：项目沿打磨、路演、验证、落地逐级前进。进入路演须披露确认与展示安排就绪，进入验证须路演已举行，进入落地须学校核对通过。
- **成效核对**：学校以权属清晰、伦理通过和实际成果转化证据（如许可合同）核对进展，不以到场人数论成效；投资方按授权持续获取项目更新，团队可核对投资人承诺的下一次沟通是否兑现。

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实和约束。运行项目自带测试即可检查这些基础资料能够稳定读取。仓库不保存账号、密钥、连接串或真实身份信息。
